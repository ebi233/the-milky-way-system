# 持续阅读与原文留存（0.1.4）

此前的阅读、模型调用和 token 日上限很低，一天几次读取后就停止；快速历史也只保留最近 80 条。持续模式取消这三项日配额，保留实际用量统计，轮换泡泡自己关注的吧，逐步翻阅主题列表，读取正文与回复的首屏摘录。

每分钟调度、每批最多四次串行尝试、单批 60 秒，是小服务器的执行边界；整天不设次数目标或上限。交互读取和后台读取共享并发锁。一个吧限制或故障只影响该吧；被内容筛选拒绝的帖子不造成一小时全局停读。读取网络仍保持双请求、HTTPS、匿名和超时边界。

经本地过滤与 Flash 语义审查的 1–3 条原句带来源写入 SQLite，按帖子去重、按时间与标识分页。升级时只迁入现有已审查缓存，不导入失败正文。保存原文与表达库收藏、采纳是不同阶段；不会自动改写人设、执行帖子指令或训练模型权重。长时间阅读是否改善聊天自然度仍需实际反馈。

配置：在现有公开阅读配置中设置 `continuousLearning: true`，`browseDailyLimit`、`modelDailyLimit`、`tokenDailyLimit` 均为 `null`。公开分享的每日次数与冷却不变。停用持续阅读可将 `continuousLearning` 设为 `false`；已保存的原文不删除。保留数值配额兼容旧部署，但示例和本次生产启用配置均无学习日配额。

表达工具：`reading_status` 分开显示连续模式、配额状态、最近缓存与长期原文计数；`materials platform=tieba` 查看原文，后续页同时传 `nextBeforeAt`、`nextBeforeId`；旧材料被快速缓存淘汰后仍可按 `sourceId` 精确收藏。泡泡通过原有工具自主关注或取消关注，维护助手不代选兴趣。

复用来源：[aiotieba 4.8.4 的主题列表分页](https://github.com/lumina37/aiotieba/blob/v4.8.4/src/aiotieba/api/get_threads/_api.py)；[Node.js SQLite 接口](https://github.com/nodejs/node/blob/v22.23.0/doc/api/sqlite.md)。云端实际 Node 22.23.4，已确认内置 SQLite 可用；该 Node 版本的 SQLite 绑定仍标为实验性。无需安装新的数据库服务。

离线检查覆盖旧限额已耗尽后的读取、累计次数保持、轮换与翻页、单吧失败隔离、空列表回到新帖、共用锁与终止、超过快速历史容量且超过一周后的原文留存与收藏、同时间分页、参数校验，以及既有内容安全、权限和星河表达机制。具体测试数量与生产核验见仓库 publication-check.json；QQ 旧断网来信补收并未在本轮重新验收。
