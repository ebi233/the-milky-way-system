# 星河系统的构建与作用

## 1. 状态中枢

`state-kernel.mjs` 统一读取和更新时的衰减计算。每条观测包含取值、置信度、时间、会话和来源；未来时间、低置信度、过期和跨会话资料被排除。同一证据不因为换一个消息编号或再次读取就增加权重。

默认情绪半衰期 90 分钟、活动状态半衰期 4 小时；实际参数可在有限范围调整。模拟昼夜节律只提供活动基线，不代表角色真的睡过觉或吃过东西。

运行读取小快照，不每轮加载原始大型状态。对外的 xinghe 与兼容字段 tidal 指向同一套记录。

## 2. 事件理解与关系分离

符合来源条件的普通主私聊会复用已有的一次 Flash/off 评估，并移到回复前，等待最多 8 秒。输入包括当前消息、至多四条近期可见对话、相关关系原话和衰减后的先前估计。超时或失败仍可继续聊天；成功、失败和结果不明均留下消息凭据，避免同一条再走旧回复后评估重复计费。

四种内容分开处理：

- 当前原话：用户确实说出的文字及来源。
- 事件解释：模型对当前来意的解释，允许修正。
- 当下反应：短时估计，不回填成角色已经表达过的情绪。
- 长期关系依据：主账号明确说过的关系、称呼、沟通、自主权和联系边界，独立保存，不随情绪衰减。

共同兴趣或邀请不会自动变成亲密关系；单方原话不代表双方同意。关系参考按当前话题选最多两项，逐项装入预算。事件缓存最多 32 条 / 128 KiB，关系档案独立限 64 KiB；不是每轮把整个档案塞进提示。

## 3. 记忆与遗忘

`memory.mjs` 与既有长期记忆模块配合，先确定最新版本，再判断有效期和当前适用性。明确纠正优先；不能在新版本过期后重新启用已被取代的旧结论。

遗忘主要是检索优先级衰减，不是随意删除原记录。读取不强化。普通记忆默认半衰期 14 天；有明确来源的偏好和纠正有额外规则。检索检查来源、时间、会话与容量，未知来源不补造。

## 4. 有依据的联想

`association.mjs` / `recall-context.mjs` 只从已通过筛选的记忆寻找关联。支持有限换说法和相邻真人话题承接，承接仅一跳且限制在真实 15 分钟窗口。最多提供一个可选连接，附来源；不把联想写回为共同经历。

## 5. 动机与抉择

状态、当前是否有真人来信、可继续话题和近期实际回执共同影响候选评分。主动活动选择“安静”时，调度确实跳过模型生成，而不是先生成一句“我安静了”。

发送成功不等于用户喜欢，没有回复不等于拒绝或遗弃。单群禁止主动发言在调度和发送处都检查；新消息、引用、点名或重启不能自动取消该配置。正常回应真实来信与空闲主动搭话分开控制。

## 6. 个人表达积累 v4

表达库保存原对话、适用话题、来源和反馈。紧邻的明确认可可保存对应例子；普通亲昵、笑声、沉默和模糊赞美不会自动推定为表达认可。

角色可自主选择真实例子先在紧密话题试用，但记录明确区分“角色选择”和“主账号认可”。同一整理条目获得两天两次独立认可，才扩大到同类场景。明确否定使条目退出自动参考，原记录保留。读取不训练、不增加认可次数；每轮最多一例，近期重复和无关话题退出。

当前用户在批评表达或讨论系统变化时，不叠加“自我分析”式提示。目标是保留亲近感并逐渐形成个人表达，而不是用短句比例、禁词数量或每轮付费改写代替自然度。

## 7. 自主调整、人格与回滚

`self_state` 提供 read / events / memory / diagnostics / preview / edit / history / rollback。九个参数有范围、版本检查、修改原因和容量限制；只在可信主账号直接私聊中开放。该工具不能修改服务器、账号密钥或跨会话隐私权限。

`self_persona` 单独管理完整人格版本，保留原版及原因、校验值和回滚。发布包不含泡泡私人原人格，也不把维护助手代写当成角色自主修改。

## 上下文预算与成本

星河当前参考总长不超过 1200 字符。模块三至七不新增每轮模型调用；事件理解复用既有评估，但前移会影响首字等待，输入/输出变化也会影响 token 费用。不能由“调用次数没增加”推导“费用没有增加”。

模型仍保留预训练能力；本系统不会自动训练模型权重，也不保证完全消除模型的惯常表达。自然度、语义准确性、费用和长期连续性需要单独用真实对话验证。
