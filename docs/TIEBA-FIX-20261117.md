# 贴吧聊天入口与别名修复 · 2026-11-17

本轮修复“后台能读，但聊天模型仍去普通网页抓取并报告无法进入”的接线缺口。上一版的后台读取成功和隔离测试，不能代表聊天中的主动阅读流程已跑通；本次核对了实际工具调用记录并补齐入口。

## 原因与证据

聊天模型确实调用了阅读列表和关注工具，添加了自己的兴趣。但当用户让它进吧阅读时，只能列出已有材料，没有即时阅读动作。缓存当时尚无贴吧文章，它随后调用普通 `web_fetch`，收到百度安全验证页面和 HTTP 403。后来被问到学了什么时，没有重新查询读取结果，沿用了这次失败的印象。

后台随后实际保存过一篇经过语义审查的主题正文与回复，共 3 条原句。因此“整个贴吧进不去”和“只从标题学习”均不能代表当前读取状态，也不能作为已经学习的证据。公开报告不包含真实会话、模型内部推理或私人兴趣理由。

另一个实际失败来自贴吧名称解析：请求“花卉”时，主题列表返回正式吧名“花”，旧代码因名称不一致拒绝继续。修复前以正式服务账号复现 `source_mismatch`；修复后同账号取得 2 条正文/回复，并保留请求名称、正式名称和吧编号。没有只删除校验条件：正文仍必须同时匹配主题列表的吧编号、正式名以及选中主题编号。

## 已改变的行为

- `expression_library reading_status`：查询专用读取器是否就绪、最近尝试和成功时间、剩余额度，并返回已有贴吧原文。
- `expression_library browse_forum`：可选 `forum`，立即读取一个已关注的吧。与后台使用同一服务、并发锁、日预算、内容过滤和语义审查；不会发帖或触发 QQ 空间发布。
- `expression_library materials platform=tieba`：只取贴吧缓存，避免其他平台或私人用语反馈混在结果中；此动作不联网，不增加模型调用。
- 列表结果带下一步入口，工具说明区分缓存、读取成功与收藏/采用，查询学习成果还需看已有表达库记录。
- 每次主动读取仍受 5 分钟间隔、平台退避及既有日限额约束。额度用完时返回明确原因，已有原文继续可读；未重置额度。
- 取消、来源不符和审查拒绝不返回未经审查的正文；群聊、访客和未知身份不能查询或触发该私人阅读入口。
- 新记录保留 `forum` 与 `resolvedForum`。历史记录若没有吧名，不猜测补写；按平台仍可读，按指定吧名过滤时可能不含这些旧记录。

## 验证与上线

新增 11 项即时阅读行为检查和 5 项别名检查；连同原有 22 项贴吧 Node 检查、10 项读取器检查及 42 项星河回归，本轮共 90 项通过。覆盖同一预算和锁、缓存回退、权限、空列表、关闭、退避、未关注吧、语义拒绝、取消及别名归属匹配。没有重跑或重复计入未改动的 QQ 历史测试。

正式云端部署通过，QQ 在线，209 项受管理文件校验一致；即时阅读服务在宿主内绑定就绪。以实际表达库函数读取云端现存数据，返回 3 条经过审查的正文片段。此验证不冒充模型已经再次主动调用，更不冒充表达改善。今日共享浏览额度已耗尽，没有提高或重置预算来制作成功记录。

本地应急副本同步代码，194 项清单核对通过，保持停止。保留原人设、表达库、关注选择、Flash/max、单群静默和资源上限，未重启 NapCat。变更前已备份，代码回退不覆盖新增私人语料。
